# Closeout — porting

## Summary

- Synthesized all five upstream artifacts into a self-sufficient
  reverse-engineering bundle: system summary, concept-named layer map,
  18-feature contract table sorted by porting priority, protocol and state
  notes, 13 consolidated portability hazards, and a full defect synthesis.
- Assigned a disposition and a **required design consequence** to all 39
  defects, with a sketched acceptance test for each of the five high
  findings.
- Closed `contracts-CF1`, `contracts-CF2`, and `protocols-CF1` with explicit
  decisions rather than deferrals.

## The three decisions

**1. Break the all-or-nothing contract — deliberately.** Two passing tests
assert that a mid-run failure discards all recognized pages. Rather than
choosing between the tests and defect D2.1, the invariant they conflate
splits cleanly:

- *Preserve:* never leave a corrupt or partial file at the destination, and
  never destroy an existing output except on a successful complete write.
- *Drop:* discard all completed work when any page fails — this protects
  nothing; it is a side effect of saving once at the end.

Writing partial results to a separate, clearly-named artifact satisfies both.
`test_late_page_failure_preserves_existing_output` keeps passing unchanged;
only `test_late_page_failure_leaves_no_new_output` needs rewording.

**2. Fix the progress formula, rewrite the test.** Nothing external depends
on it, and the current behavior makes a working app look hung.

**3. Extend the event schema and state machine together.** Cancellation,
per-page retry, concurrent recognition, and resume all need the same four
missing primitives — job identifier, monotonic sequence number, a CANCELLING
state, and an error state. Adding any one feature without them reintroduces
exactly the races the current design avoids only by being strictly
sequential.

## Compression boundary

The bundle deliberately omits two things and names both in the Source Index
with explicit deep-read triggers: the 40 black-box acceptance scenarios
(contracts) and the full nine-event payload schema plus 21-transition state
machine (protocols). Routed to the spec as `porting-CF3`. Everything else
load-bearing is carried inline, so the spec phase can start from this one
artifact.
