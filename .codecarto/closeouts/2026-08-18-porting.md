# Closeout — porting

## Summary

- Synthesized all five upstream artifacts into a self-sufficient
  reverse-engineering bundle: system summary, concept-named layer map,
  19-feature contract table sorted by porting priority, protocol and state
  notes, 15 consolidated hazards, and a full defect synthesis.
- Assigned a disposition and a **required design consequence** to all 41
  defects, with a sketched acceptance test for each of the four high findings.
- Closed `contracts-CF1`, `contracts-CF2`, `contracts-CF4`, and
  `protocols-CF1` with explicit decisions rather than deferrals.

## The four decisions

**1. Break the all-or-nothing contract — deliberately.** Two *passing*
service-suite tests assert that a mid-run failure discards all recognized
pages. Rather than choosing between the tests and D2.1, the invariant they
conflate splits cleanly: **preserve** "never leave a corrupt or partial file
at the destination, and never destroy existing output except on a successful
complete write"; **drop** "discard all completed work when any page fails,"
which protects nothing and is merely a side effect of saving once at the end.
Writing partial results to a separate, clearly-named artifact satisfies both;
only one test needs rewording.

**2. Fix the progress formula, rewrite the tests.** Nothing external depends
on it, and the behavior makes a working app look hung. Cheaper than it looked:
the tests in question are GUI-suite tests that error at collection headlessly.

**3. Extend the event schema and state machine together.** Cancellation,
per-page retry, concurrent recognition, and resume all need the same four
missing primitives — job identifier, monotonic sequence number, a CANCELLING
state, and an error state. Adding any one without them reintroduces the races
this design avoids only by being strictly sequential.

**4. Carry the two known-failing scenarios as MUST rules.** Of 42 acceptance
scenarios, exactly two describe behavior the implementation *demonstrably
fails*, both found by execution: row 41 (quitting mid-run must not leak the
render directory — proven by probe) and row 42 (a headless test run must not
produce collection errors — measured). A faithful port would reproduce both.

## The caveat the bundle leads with

The specification is **two-tier**, and the bundle says so up front rather than
averaging it away. The service suite passes, so its contracts are verified.
The GUI suites error at collection, so 14 of the 42 acceptance rows are
`asserted-not-verified`. The GUI is simultaneously the only interactive
surface and the least-evidenced half of the spec — worth knowing before
trusting it as a parity harness.

## Compression boundary

Two things are deliberately omitted and named in the Source Index with
explicit triggers: the 42 acceptance scenarios and the full event/state
tables. Routed as `porting-CF3`, which also requires the spec carry the
verification-status column forward (convention C04). Everything else
load-bearing is inline, so the spec can start from this one artifact.
